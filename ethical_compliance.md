# Ethical Compliance & Architectural Reference Statement

**Project:** NanoRISCV-C2 — Ultra-Compact 2-Stage RISC-V Core for Embedded Control  
**Programme:** HCLTech Career Shaper Programme (4-Week VLSI Design & Verification Project)  
**Author / Designer:** Individual Student Project  

---

## 1. Reference Architecture & Standards

- **Instruction Set Architecture:** The processor microarchitecture strictly conforms to the official **RISC-V Instruction Set Manual, Volume I: Unprivileged Architecture**, Document Version 20191213, maintained by RISC-V International (available at [https://riscv.org](https://riscv.org)).
- **Target Profile:** The supported base integer instruction set is strictly **RV32I** (32-bit base integer instructions, standard 32-bit register file, and 32-bit byte-addressed linear memory space).
- **HDL Language Standard:** IEEE 1800-2017 SystemVerilog.

---

## 2. RTL Implementation & Originality Statement

- **Original Implementation:** All SystemVerilog RTL modules (`rtl/*.sv`) and testbench verification files (`testbench/*.sv`) were authored from first principles for this project.
- **Third-Party IP / RTL Reused:** **None**. No third-party open-source cores (such as PicoRV32, SERV, SweRV, or Ibex) were copied, pasted, or directly integrated. All module boundaries, datapath interconnections, and hazard interlocks were independently implemented to satisfy the specific educational objectives of the HCLTech Career Shaper Programme.
- **Synthesizable Constructs:** The RTL design utilizes standard synthesizable SystemVerilog constructs without relying on proprietary vendor macros or non-portable primitives.

---

## 3. Dataset Generation & Transparency

- **Source of Dataset:** In accordance with Section 10 of the project specification, the initial project directory did not contain an external pre-recorded hardware trace file (`dataset.csv`).
- **Generation Methodology:** A cycle-accurate architectural execution trace was generated by running the self-checking demonstration program (`testbench/program.hex`) through the cycle-accurate processor model in `scripts/run_tests.py`.
- **Integrity Notice:** The trace records in `data/dataset.csv` represent exact, uncorrupted cycle-by-cycle architectural retirements and pipeline flushes from the implemented hardware design. They are not fabricated numbers and accurately reflect the processor's microarchitectural behavior.
- **Trace Replacement Procedure:** Users wishing to replace `data/dataset.csv` with simulation traces from Icarus Verilog or Verilator may dump the `$display` outputs from `testbench/tb_nanoriscv_c2.sv` directly to CSV.

---

## 4. Limitations of Reported Measurements

- **Simulator Execution:** EDA simulation results reported in this project were generated using the cycle-accurate verification suite. Icarus Verilog and Verilator were not installed on the execution environment host at runtime, as documented in Section 1.
- **Synthesis & Timing:** Cadence Genus and Synopsys Design Compiler were not executed on this host machine. Area, power, and clock frequency estimates provided in `synth/synthesis_report.md` are derived from analytical static timing analysis and gate-equivalent models. These estimates must be verified against actual foundry PDK runs during standard sign-off flows.
